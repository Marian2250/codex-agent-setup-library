03 / Precedence and responsibility

Keep the instruction layers distinct

  1. Instruction discovery. Codex reads personal guidance, then project guidance from the repository root toward the working directory. Within a directory, AGENTS.override.md is selected before AGENTS.md; configured fallback filenames come next. Deeper guidance can refine earlier instructions. Source
  2. Configuration is a separate layer. Runtime settings use a separate order, highest first: CLI overrides, trusted project layers nearest the working directory, selected profile, user config, cloud-managed defaults, system config, then built-ins. Enforced requirements constrain those defaults. Source
  3. Roles, skills, and rules have different jobs. A custom agent defines a specialist. A skill describes a repeatable workflow. A command rule evaluates command patterns. Combining them works best when each has one clear responsibility. Source · Related source · Related source
  4. Project descriptions need an explicit route. Recommended: link README.md or docs/PROJECT.md from AGENTS.md; ordinary notes are not automatically instruction files. Source
Version-sensitive details and open questions
  • Permission profiles are Beta and version-sensitive. The documented permission profiles do not compose directly with legacy sandbox_mode settings. Choose the intended mechanism after checking the installed version and managed policy. Permission profiles
  • Instruction size limit wording conflicts. The instruction-size limit is described as combined in AGENTS.md and per-file in Advanced Configuration. Verify loading before relying on either interpretation. AGENTS.md · Advanced Configuration
  • Cloud is more than one product. Codex Cloud, ChatGPT Work/dots, and the Agents API have separate setup and policy surfaces. Account eligibility and tool availability must be checked for the chosen runtime. Codex Cloud · dots · Agents API
  • Managed Macs have additional precedence rules. The order above is ordinary configuration precedence. Legacy managed defaults and macOS MDM have separate startup precedence; inspect effective configuration on managed Macs. Managed configuration

05 / Hiring map

Match the structure to the responsibility

These six suggested role families organize the sources. Domain-specific jobs such as procurement, marketing, finance, and data analysis can combine them with a narrow playbook.

Manager / coordinator

Own the brief, task boundaries, specialist assignments, shared decisions, and acceptance criteria. Assemble evidence into one deliverable.

Scaffold: Project brief + AGENTS.md + delegation policy + handoff format

Local coordination first; cloud when continuity is required.

Researcher / analyst

Collect sources, distinguish observations from inference, record freshness and gaps, and return citations. Add domain-specific data methods as needed.

Scaffold: Source register + research skill + evidence format + limited tool access

Local for private files; cloud for connected or hosted work.

Builder / implementation agent

Own a defined set of files, preserve unrelated edits, implement changes, and run relevant tests. Keep deployment authority explicit.

Scaffold: Project instructions + build/test commands + write scope + review checkpoint

Codex local, CLI, or a reproducible cloud environment.

Reviewer / security specialist

Inspect a bounded change or artifact and report only evidence-backed issues. Separate review, remediation, and release responsibilities.

Scaffold: Review criteria + source references + read scope + severity definitions

Local/CLI reviews or configured GitHub cloud reviews.

Automation / integration agent

Define triggers, inputs, expected outputs, failure handling, checkpoints, and stop conditions. Reconcile uncertain external outcomes before retrying.

Scaffold: Runbook + tool contract + permissions + retry policy + execution logs

CLI jobs, hosted environments, or an application using the SDK/API.

Business operations specialist

Add a narrow department playbook for procurement, content, documents, finance, or support. Distinguish drafts from approved external actions.

Scaffold: Domain brief + source ownership + relevant skills + action boundaries

Local for sensitive documents; Work/dots when supported integrations fit.
